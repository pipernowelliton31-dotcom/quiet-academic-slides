# Layout grammar and page jobs

Study these as **semantic composition recipes**, not compulsory slide layouts. Refer to `assets/reference-pages/reference-NN.jpg` for actual spatial examples. Avoid cloning all seven pages into every new presentation. Use the roster that fits the message.

## 1. Editorial hero (`reference-01.jpg`)

**Question:** Why should this matter to the audience? Create an invitation, not an abstract.

**Original page:** a large image occupies roughly the right side; left paper zone has a fine opening rule, 48 pt two-line serif title, short sans subtitle, a single question, and quiet speaker metadata. A small contrasting noise panel establishes the central mystery.

**Adaptation:** dominant verified image or empirical visual, title under ~6 words per line, one concise intellectual hook. If no suitable image exists, use an elegant data/diagram hero rather than a decorative stock shot. Never add unrelated stickers, brand marks, icons, or a thick border. Speaker information only when the delivery context calls for it.

## 2. Three-question argument arc (`reference-02.jpg`)

**Question:** Which three steps will make the audience understand?

**Original page:** horizontal thread with three colored nodes and numerals 01/02/03 aligned to the same x coordinates as their questions; one short caption per question. Main copy centered beneath each dot, no bulky cards.

**Adaptation:** align numbers, dots, headings and descriptions on one invisible column grid. Captions must add a distinct operator: "add noise, estimate it", "predict, sample, repeat", not vague motivational slogans. Use 2–4 nodes only when topology actually calls for it. For 5+ steps, choose a timeline or grouped structure.

## 3. Two-lane mechanism (`reference-03.jpg`)

**Question:** What changes in phase A versus phase B, and what is compared?

**Original page:** opposing half-canvas lanes split by hairline; image sequences or states at top; formula beside relevant process; a bottom comparison strip gives target, estimate and loss. Green marks known quantity, blue marks predicted quantity.

**Adaptation:** left lane = known transformation, right = learned response or alternative branch; bottom stripe = objective, invariant, or difference. An equation must be adjacent to the operator it formalizes. Align representations, arrows, math baselines and state names. Keep real versus predicted color semantics identical across the slide. The initial/final samples must match their labels (pure noise should visually be noise).

## 4. Sequential/iterative mechanism (`reference-04.jpg`)

**Question:** What happens step by step or across time?

**Original page:** light paper, dominant horizontal state transition, compact probability equation above, left/right endpoints as visuals, three named phases below: predict, sample, repeat. A recurrence is explicit; no sudden dark background.

**Adaptation:** progressive time/state row, minimal step symbols, appropriately directional arrows. Preserve state ordering. Show a loop/ellipses only if recurring transitions exist. If comparing trajectories, use two clearly named rows and only true comparable endpoints. An image of the end result is not a proof of the path; use actual trajectory frames when claiming measured progression.

## 5. Relationship matrix with output (`reference-05.jpg`)

**Question:** Which inputs interact with which features, and how does the result flow?

**Original page:** italic prompt line; compact 4x4 colored grid with row/column meanings; one restrained formula and short verb phrase; bottom update flow; full-aspect right-side illustration. No giant Transformer equation.

**Adaptation:** use a small matrix or heatmap when explaining many-to-many relations; label axes clearly. Never use a matrix as decoration. Route conditional information to the transformation node, not directly into the completed output. Decoder/output stage follows final representation. Keep the right image intact: `contain` rather than mindless crop. If a matrix is inappropriate, replace with a relationship map or Sankey-like diagram while preserving the same quiet alignment.

## 6. Research/open question (`reference-06.jpg`)

**Question:** What still needs to be solved or decided?

**Original page:** left large serif question and one-sentence research mission; right paired evidence areas (related approach, user's experiment) with minimal descriptions. Vertical separator creates clean reading order.

**Adaptation:** ask one precise unresolved question. Support with authentic evidence, not invented metrics. Distinguish background methods from the present work clearly and tactfully. A label such as "Approach" or "Our experiment" can replace verbose defensive footnotes on-slide; keep provenance in notes when needed.

## 7. Returning close (`reference-07.jpg`)

**Question:** What idea remains after the last slide?

**Original page:** return to an image-led split, left large serif "Thank you", short answer to the cover mystery, and a three-word recap. The right field echoes the opening image mood. Quiet name/date metadata only if required.

**Adaptation:** refrain/motif should echo Slide 1 conceptually, not literally duplicate the exact picture. State a real takeaway, not a generic "Questions?" wall. If no closing image was established, a refined single-line conclusion on warm paper is stronger than a forced visual.

## Extending to other subjects

- **Benchmark:** central bar/line chart with an editorial serif claim above, micro legend, and one annotated turning point. Native, correctly scaled axes and real data.
- **Theorem or derivation:** one main equation at visual center; steps in aligned columns; emphasis by geometric grouping and blue/green variable roles, not heavy colored boxes.
- **A/B comparison:** two balanced half-page evidence images or metrics, a skinny shared evaluation axis, no third decorative panel.
- **Ablation or failure cases:** grid of consistent real outputs with aligned captions and a restrained comparison key. Never fabricate photographs or experiment numbers.
- **Decision recommendation:** one line thesis, 2–3 evidence blocks with differing widths, one clear implication. No presentation-cliché KPI badges.
- **Long talks:** alternate between dense reasoning pages and intentionally quiet synthesis pages. Keep token system stable as page count grows.

## Structural questions to ask before drawing

1. What single claim should the audience retain?
2. Which variables, states, entities, events, or measurements actually exist?
3. Are relations sequential, symmetric, hierarchical, causal, probabilistic, or many-to-many?
4. Which original material is verified evidence versus teaching illustration?
5. Can a carefully arranged visual replace one paragraph without losing rigor?
6. What visual element would become confusing if removed? Keep only those elements and their necessary labels.
